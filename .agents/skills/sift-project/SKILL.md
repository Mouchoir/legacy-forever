# sift project profile: legacy-forever

Legacy Forever is a World of Warcraft: Forever (Classic beta client, Interface 16001, Lua 5.1)
addon that puts unfinished Legacy challenges on the world map and in the objective tracker.
The game client loads the files listed in `LegacyForever.toc`; the BigWigs packager (`.pkgmeta`)
builds the release zip for CurseForge, Wago and GitHub. `Data/Legacy.lua` is generated by the
stdlib-only Python in `tools/` from wago.tools DB2 exports; a daily workflow regenerates it.
The specs in `tests/` load every shipped Lua file under stubs, so logic is testable headless; frames, menus,
tooltips and the tracker are checked in the client.

## Gate

Run in order from the repository root. All must pass before and after any audit slice.

| Step | Command | Pass means |
|---|---|---|
| Format (Lua) | `stylua --check .` (StyLua 2.5.2) | exit 0 |
| Format (Python) | `ruff format --check .` (Ruff 0.16.8) | exit 0 |
| Lint (Lua) | `luacheck .` | `0 warnings / 0 errors` |
| Lint (Python) | `ruff check .` | `All checks passed!` |
| Types (Lua) | `tools/typecheck.sh` | exit 0, no LuaLS diagnostics or multi-value lint findings |
| Tests | `for s in tests/*_spec.lua; do luajit "$s" \|\| exit 1; done` | exit 0 (`model_spec: N checks passed`) |
| Workflows | `actionlint && zizmor --offline .github` | exit 0, no findings |
| Secrets | `gitleaks git --redact --no-banner .` | `no leaks found` |
| Changelog, project rules | `python3 tools/changelog.py --check && python3 .sift/gate.py --base origin/main && python3 .sift/agents.py check` | exit 0 |

CI (`.github/workflows/ci.yml`) runs all of these with the versions above pinned. Where actionlint
or zizmor is not installed, run `uvx --from actionlint-py==1.7.12.24 actionlint` and
`uvx zizmor==1.30.1 --offline .github`.
Ruff ignores `NO_COLOR` when `FORCE_COLOR` is set in the shell; `unset FORCE_COLOR` for
parseable output. Python type checking is not gated: `uvx ty check tools` reports a handful of
diagnostics (11 in 2026-09) on untyped JSON/CSV dict values; they are not defects.

## Evidence

On-demand tools for audits. Output is candidates, never verdicts.

| Concern | Command | Known false positives |
|---|---|---|
| Dead code (Lua) | `luacheck .` (unused locals/args; currently clean) | mixin methods called by the host (see live roots) |
| Dead code (Python) | `uvx vulture tools --min-confidence 60` | argparse handlers |
| Duplication | `npx --yes jscpd@4 --silent --reporters json --output .sift/runs/jscpd --ignore "**/.sift/**,Data/**" .` | XML template blocks in `UI/Map.xml`/`UI/Completion.xml` (UI boilerplate) |
| Globals drift | check runtime globals against `.luacheckrc`, pinned WoW annotations and `types/forever.lua` | no LuaLS globals whitelist |

`rg` with no path argument reads stdin in a non-interactive shell and hangs: always pass `.`. Plain `rg` skips
hidden paths; add `--hidden` when a search must cover `.github/`.

sift's inventory marks `Core/Model.lua` and `tools/legacy_render.py` as generated because the word
appears in their first five lines; only `Data/Legacy.lua` is generated.

Behaviour-preserving proof for `tools/`: regenerate and diff against the committed output.
`python3 tools/gen_legacy.py --offline` needs every source in `tools/.cache` (gitignored; copy it
from another checkout or run without `--offline` to fetch the pinned build), and `python3
tools/screenshots.py` rewrites `docs/screenshots/*.png`. A clean `git status` afterwards proves the
edit changed nothing. `gen_legacy.py --offline` fails when the cache holds an older build than
`BUILD`; run it once online to fetch the pinned build. The standards slice reads the pinned
`wow-forever-addon` pack from the sift cache (`agents.py standards` prints its path);
`SIFT_STANDARDS_PATH=$HOME/skills` overrides it with a local checkout that may not match the pin.

## Live roots

- `LegacyForever.toc` file list: load order `Locales/enUS.lua` (then any `Locales/<locale>.lua`), `Data/Legacy.lua, Core, Saved, ForeverFamily, WhatsNew, Model, Live, Quests, Navigate,
  ZoneCompletion, TrackerHost, Tracker, UI/Completion.xml, Completion, Settings, MapContents, UI/Map.xml, Map, API`; never reorder as formatting.
- `## SavedVariables: LegacyForeverDB`: persisted keys `tracked`, `zoneCompletion`,
  `flightPaths`, `trackerHost`, `showAreas`, `whatsNew`, `lastVersion`, named only in `Core/Saved.lua`, and `suggestFamily` (default
  in `Core/Saved.lua`) and `familyDismissed`, which the shared `UI/ForeverFamily.lua` (byte-identical in all five addons; never edit it
  here) also reads and writes through `ns.FamilyDB()`; old keys in players' saved data are compatibility obligations (`companions`, pre-0.8, is
  migrated to `suggestFamily` once and dropped).
- `## AddonCompartmentFunc: LegacyForever_OnAddonCompartmentClick`: global called by the client.
- `SLASH_LEGACYFOREVER1/2` + `SlashCmdList.LEGACYFOREVER` (Core/Core.lua): `/lf`, `/lf audit`, `/lf criteria`.
- XML `mixin=` names (`LegacyForeverPinMixin`, `LegacyForeverAreaPinMixin`, `LegacyForeverMapButtonMixin`,
  `LegacyForeverZoneOverlayMixin`) and `<Scripts>` `method=` handlers (`OnLoad`, `OnShow`, `OnHide`, `OnClick`,
  `OnEnter`, `OnLeave`).
- Methods the map canvas calls on data providers and pins by name (`RefreshAllData`,
  `RemoveAllData`, `OnAcquired`, `OnReleased`, `OnMouseEnter`, `OnMouseLeave`), tracker-module
  methods (`LayoutContents`, `OnBlockHeaderClick/Enter/Leave`), and
  addon-owned callback targets (tracker `SetCollapsed`); native manager hooks are forbidden.
- Event names registered in `Core/Live.lua` and callbacks via `EventRegistry`/`EventUtil`.
- `ns.*` fields: each file receives the shared addon table `ns`; a field set in one file is read
  in another with no import. Search all `.lua` files, including `tests/`.
- `tools/gen_legacy.py` output format: `Data/Legacy.lua` keys are the contract read through `ns.Data` by
  every TOC Lua file after it (`rg -n 'ns\.Data' .`) and by `tests/data_spec.lua`.
- `tools/legacy_render.py`: imported by `gen_legacy.py` and `screenshots.py`; `tools/db2.py` and
  `tools/locations.py`: imported by `gen_legacy.py`;
  `tools/screenshots.py`: run by hand after UI changes (needs Pillow and `wowmock`), and runs
  `tools/screenshots_model.lua` under LuaJIT so the scenes come from the real `Core/Model.lua`;
  `tools/check_diagnostics.py`, `tools/lint_multivalue.py`: run by `tools/typecheck.sh`.
- `tools/latest_build.py`: run by `.github/workflows/refresh-data.yml`; `tools/changelog.py`:
  run by `release.yml` and (`--check`) `ci.yml`; `refresh-data.yml` also rewrites the `BUILD = "..."` and
  `SOURCE_DATE = "..."` lines of `gen_legacy.py` with `sed`, so keep them single-line.

## Open questions for reviewers

- SavedVariables timing: `LegacyForever.toc` sets `LoadSavedVariablesFirst: 1` and Core/Saved.lua relies
  on it, but UI/Completion.lua still defers for a client that might ignore the directive. Until that
  is confirmed in game, the `LegacyForeverDB or {}` guard in `Core/Saved.lua` is not defensive noise.
- FrameXML helpers (`tContains`, `tIndexOf`, `CountTable`, `Mixin`) are the platform for the
  reinvented-wheel lens, but only `tContains` and `Mixin` are confirmed on this client.

## Conventions

- Every TOC Lua file receives `local <name>, ns = ...` (Core/Core.lua aliases `addon` to `ns`); modules are
  `local X = {}; ns.X = X`.
- Tabs, 120 columns, double quotes (StyLua). Python: 4 spaces, 120 columns (Ruff).
- Comments explain game-client behaviour and why ("Forever's ruleset refuses ..."), not what.
- Pure logic lives in `Core/Model.lua` with no WoW API calls so the tests can load it;
  `UI/MapContents.lua` decides what a map shows (button count, menu entries, badges, pins, shaded areas, hover target)
  as plain tables, so `UI/Map.lua` holds only frames, menus and tooltips;
  `Core/Live.lua` owns the snapshot reads (exploration, flight paths, achievements, completed quests),
  while `Integrations/Quests.lua`, `UI/Map.lua` and `Core/Core.lua` still call the client directly for their own needs.
- `Core/Saved.lua` (`ns.Saved`) owns the saved switches: where a key is saved, its default, the write and the
  change notice (`Get`, `Set`, `Default`, `OnChange`). A toggle calls `ns.Saved.Set` and whoever draws from the
  switch listens with `ns.Saved.OnChange`; the Settings page rows are proxies onto it. No other file names
  `LegacyForeverDB`.
- `Core/ZoneCompletion.lua` (`ns.ZoneCompletion`) owns zone completion without a frame: a zone's or continent's
  result under "What counts" (`Result`, `Of`, `Continent`, `IsCounted`, `IsShown`), when a zone reaching 100% is
  news (`OnComplete`: the quiet window after login, once per zone, never from unticking a category or with both
  surfaces off) and the one change notice (`OnChange`). `UI/Completion.lua` (tracker section, map corner, toast,
  menu), `UI/Map.lua`, `UI/MapContents.lua` and `Core/API.lua` read and listen there; `tests/zone_completion_spec.lua`
  drives it with a stubbed clock.
- Python generator fails loud: malformed input raises `ValueError` with a `name:line` label.
- Commit messages: Conventional Commits; CHANGELOG entries are prose per version.

## Risk order

Audit slices from lowest to highest risk:

1. `tools/`: offline, output verified by `tests/data_spec.lua`
2. `tests/`, `Core/Core.lua`, `UI/Tracker.lua`: small, isolated
3. `Core/Model.lua`: pure, covered by `tests/model_spec.lua`
4. `Core/Live.lua`: live game state and SavedVariables
5. `UI/Completion.lua`, `UI/Completion.xml`, `UI/Map.lua`, `UI/Map.xml`: UI hooks into Blizzard frames,
   untestable headless; taint risk

## Settled

Shapes that look like defects here but are not. Reviewers and verifiers read this before raising a
finding.

- nil guard after a `number?` return (defensive-noise): a nil guard right after `ParseKey` or
  another `number?` return narrows the type for LuaLS; removing it trades the branch for a
  `---@cast`, e.g. `Core/Model.lua`
- Tracker `uiOrder` `0` (defensive-noise): Legacy Forever's registered slot in WFA-5, not a missing
  negative, e.g. `UI/Tracker.lua`
- sibling names in the shared tracker host (comment-narration, dead-code): `UI/TrackerHost.lua`,
  `tests/tracker_host_spec.lua` and `tests/tracker_geometry_spec.lua` are kept byte-identical with the copies
  in the sibling addon repositories, so `/agf tracker`, `AGF_TRACKER_HOSTS` and `lint_copy` refer to those
  copies; an edit to any of the three is the owner's decision across all copies, e.g. `UI/TrackerHost.lua`

## Anti-patterns

Shapes this codebase has produced more than once and a reviewer confirmed. An audit guards a
confirmed defect of one of these shapes with `settled:<name>`.

- **mock-or-empty**: `x or {}` around a mock reader that always returns a table (defensive-noise),
  e.g. the former Python port of `Core/Model.lua` in `tools/screenshots.py`
- **session-narration**: docs narrating the session that wrote them, "a simulated build bump ...",
  "changes from the previous slice" (session-residue), e.g. `tools/README.md`
- **unfailable-check**: an assertion that an earlier assertion, or the spec's own literal, already decides,
  so no change to the code under test can fail it (test-plumbing), e.g. `tests/data_spec.lua`

## Project rules and lenses

- Rules: `file-size-no-growth` (`.sift/scripts/`, from the sift catalog) fails a change that adds
  a file over 1000 lines or grows one. Generated `Data/*.lua` is excluded. `workflow-hashfiles-path`
  (`.sift/scripts/`) fails a workflow whose `hashFiles` names a literal path that does not exist.
- The BigWigs packager drops every dot-prefixed path itself, so `.pkgmeta` lists only
  non-dot ignores; a dot entry there is dead config.
- Lenses: none yet.

The type gate also runs `python3 -m tools.lint_taint` and `python3 tools/typecheck_coverage.py`: native-method hooks, shared UI-state writes and omitted runtime type coverage fail CI. TrackerHost owns addon sections and pools outside Blizzard's registry; first rendering follows both native load events, deferred one frame. CI runs the private host against pinned Forever module/block/animation source.
